# Вход через Twitch — предложение, без реализации

Дата проверки документации: 2026-11-01. Регистрация приложений, внешние настройки и production не изменялись.

## Предлагаемый интерфейс

Сохранить быстрый гостевой вход. Добавить необязательный вход через Twitch: имя и фотография профиля плюс отдельный выбранный игровой персонаж. На пьедестале стоит персонаж; фотография Twitch может отображаться в профиле. Не смешивать подтверждённый Twitch-профиль и гостя с таким же ником. Обозначать подтверждённый профиль как «Twitch», без имитации официального verified badge.

## Техническая схема для обсуждения

Использовать серверный OIDC Authorization Code flow. Зарегистрировать отдельное приложение Twitch и точные callback URL, например `https://overratedkino.ru/auth/twitch/callback` и отдельный localhost callback. Для регистрации владельцу потребуется Twitch-аккаунт с 2FA. Client Secret хранить только в переменных окружения сервера, не в React/Vite, Git, URL или localStorage.

Планируемые маршруты: GET `/auth/twitch`, GET `/auth/twitch/callback`, GET `/api/me`, POST `/auth/logout`. Запрашивать только `openid` и нужные claims (sub, preferred_username, picture), без email, чата, подписок и управления каналом. Проверять одноразовые state/nonce, подпись ID token, issuer, audience, expiry и subject стандартной OIDC-библиотекой. После callback выдавать собственную ограниченную по времени сессию в HttpOnly/Secure/SameSite cookie. Не передавать Twitch access/refresh tokens клиенту и другим игрокам; если API после входа не нужен, не сохранять их дольше обработки входа. Ограничить частоту запросов, редиректы разрешать только внутри приложения, не писать auth code/token в логи.

Учётная запись должна определяться Twitch subject/ID, а не изменяемым ником или присланным клиентом полем. Room playerId и секрет переподключения остаются отдельными. Привязка текущего гостя к аккаунту возможна только из его действующей подтверждённой сессии; вход по совпавшему нику не должен давать чужое место, очки или права ведущего. Вход в существующую комнату не меняет автоматически роли и состав игроков.

## Что решить до реализации

- Нужно ли хранить историю игр, статистику, настройки персонажа между устройствами? Это требует постоянного хранилища. Файловая система Render Free его не обеспечивает. Платные услуги не подключать.
- Для первого этапа можно обойтись входом без постоянной истории: после перезапуска сервера пользователи при необходимости входят повторно. Это не решает сохранение комнат и матчей.
- Проверить доступность Twitch OAuth из российских сетей: вход через Twitch не исправляет доступность самого сайта. Гостевой режим должен оставаться рабочим при недоступности Twitch.

Перед реализацией согласовать объём отдельно: это задача по безопасности авторизации и Socket.IO. Тесты должны проверять CSRF, повторный callback, истёкшие/неверные токены, logout, повторный вход, разные устройства и невозможность забрать гостевого игрока по нику.
